# 账本 schema v2

v2 在保留两级分类身份、账户、来源行、预算和模板的基础上增加成员、借贷联系人和旧版首页偏好。业务数据只在用户设备内处理。

## 成员与联系人

- `members` 按账本和规范化名称独立。`kind=self` 是新手动记账的默认成员，显示名可改，但不能归档；`kind=unspecified` 明确表示来源没有成员证据。
- `loanPeople` 是借贷联系人，和普通成员分开。成员及联系人改名均记录显式旧名称别名，后续旧 Excel 的同一名称可复用稳定 ID。
- 普通支出、收入、转账关联 `memberId`，借贷为 `memberId=null` 并关联 `personId`。不得把借贷人误作成员，或把旧版未记录的成员伪造为“自己”。
- `ensureMemberDraft`/`ensureLoanPersonDraft` 只修改调用者私有草稿，批量导入最后统一验证。手动创建、修改、排序及归档使用公开纯命令。

## 借贷与现金

`direction=loan` 使用 `loanType=borrow/lend/repay/collect`，分别为借入/借出/还款/收款。借贷不关联收支分类或第二个账户。

原包隔离实测：基准现金 -20 元，借入 71→51，借出 13→38，还款 11→27，收款 7→34。普通收入0、支出20保持不变，旧版借贷净额依次 -71/-58/-47/-54。该序列已经固定为自动回归。

- 现金增加：借入、收款；现金减少：借出、还款。
- 待收=借出-收款；待还=借入-还款；借贷净额=待收-待还。
- 不自动抵销或删掉同一联系人相反方向的流水；不同联系人的余额独立。
- 只导入某个期间可能使待收/待还为负；保留符号和记录，不伪造此前的借贷来补齐。
- `bookBalance` 始终是账户余额合计，不再扣一次借贷净额。普通收支统计和预算不包含借贷本金。
- `transferType` 可选保留原转账类型文字，仅用于原信息保留，不改变转出/转入规则。

## v1 后向兼容

这里的 v1 指本重制工程先前的 schemaVersion=1，不表示已经支持原 App 未公开的私有“本地备份”格式；原 App 数据仍按实测 Excel 格式导入。

`legacy-v1.ts` 是冻结的旧结构验证器。`migrateState(value)` 先识别版本并严格验证原 v1 数据，再返回新副本；不会修改输入或写数据库。

每本 v1 账本增加稳定的“自己”和“未指定”成员，旧交易与旧模板关联“未指定”。保留全部旧 ID、金额、日期、时间、备注、归档状态、类别/账户关系、别名、导入批次和 `sourceRows`、预算及模板。旧页面偏好迁移为 `classic/coral`，主题明暗保持原值；新账本默认 `overview/blue`。

数据库读取先校验旧快照原始字节的 SHA-256，之后才迁移。读取不重写旧数据；后续明确保存才以新版本提交，历史保存点保留原快照。

备份外层协议仍是版本1，支持 schema v1/v2 payload。解码先认证原始 payload 的摘要（加密文件还先验证GCM），再迁移并验证。返回元数据同时包含 `sourceSchemaVersion`、当前 `schemaVersion` 和 `migrated`。新 v2 备份往返保持全部成员和借贷关系。

## 独立日、周、月预算

`Budget` 可选增加 `period`、`recurring` 和 `anchorDate`。完全没有这些字段的旧预算仍是固定 `month`，不会被迁移或自动改成循环模板。旧 `setBudget` 只更新同一固定月/类别，不能碰到恰好在同月创建的日、周模板。

新 `setPeriodBudget` / `setRecurringBudget` 默认创建循环模板：日、周、月分别拥有金额与ID，给已有ID时只编辑该项。循环模板的 `month/anchorDate` 是创建记录，不限制之后的周期；显式固定日/周的锚定日期则是其不可变窗口起点。

- `periodRange` 返回本地日历日期的包含端点区间，不用固定30天或时区秒数模拟月份。
- `periodBudgetProgress(state,bookId,date,period,weekStartsOn?)` 分别计算每个周期。没有预算时 `limitCents/remainingCents=null`，`hasBudget=false`；`displayRemainingCents=0` 对应原版首页未设置时的零。
- 周起始默认采用现有周一行为，可显式传0（周日）或1（周一），或设置 `settings.weekStartsOn`；旧缺失字段仍按周一解释，不在没有证据时改动它。
- 总体预算优先，取所有有效总体额度的最大值；没有总体时，分别合计不重叠的分类分支。同分类重复取最大，父类额度覆盖子类额度，避免首页重复覆盖。这项父子/重复类别规则是明确的新实现策略，不冒称已在原版全部验证。
- 首页周期余额按原包控制实验，仅扣有效预算所覆盖的普通支出：总体预算覆盖本周期全部支出；没有总体预算时，仅扣已配置分类/子树的支出，未配置类别不扣。`spentCents/coveredSpentCents`为实际扣款范围，`periodExpenseCents`保留整个周期的普通支出供说明。借贷和转账本金不进入预算支出。
- 合并分类按完整的日/周/月、循环/固定以及固定窗口键分组。只有原类别不同、合并后落到同一类别的预算才组合；先取同原类别的最大额度，再相加。不会把三个周期或两个固定月份合成一条，也不会删掉无关重复总体记录。

原版已实测：本期普通支出20元，月总体3000时日/周/月剩余显示0/0/2980；再设日100得到80/0/2980；再设周700得到80/680/2980。另一实验仅设未消费的交通日预算50、今日FixtureFood支出21，首页剩余为50（不是29），因此无总体时确实按覆盖类别扣款。周一边界也已由周日历史记录控制实验确认。跨月模板继续重复和父子预算的防重复覆盖策略仍区分为实现约定；代码由合成数据覆盖跨周、跨月、闰日及边界。
