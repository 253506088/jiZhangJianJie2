# 1.0.1 · MuMu Android12 启动兼容性

日期：2026-11-10。用户报告APK启动即退出，本次分别核对安装包身份和网页组件版本，不将两种问题混为同一原因。

## 核对结果

- 用户原MuMu实例0当时仅有 `com.yu.keepaccounts`，版本4.8.8(89)；没有重制版 `dev.keepaccounts.jianjie2`。用户表示可能选错文件。没有启动或读取旧App的账本，也没有卸载它。
- 原实例与新建空白测试实例均为API32（Android12），内置 `com.android.webview 110.0.5481.154.1`。
- 在空白实例安装原交付1.0.0后，原生进程持续运行，显示“请更新系统网页组件”。原因是项目将最低WebView版本定为111；这里没有复现原生Java进程闪退，不能据此声称修复了旧App的闪退。

## 修改

- 将应用最低WebView和Vite的JS/CSS编译目标统一为100，避免随Vite默认浏览器基线提高要求。
- 所有使用dvh的关键高度均添加vh回退，使较早网页组件也有有效的页面、对话框和键盘高度。
- 版本升级为1.0.1(2)，沿用相同私钥和包名，无需卸载清数据；保持无INTERNET权限与本地账本设计。
- 构建同时提供带App名称和版本的APK副本。README和构建说明明确：根目录“简洁记账.apk”是保留的原版，安装新版要选择artifacts内文件。

## 验证

- 专用空白MuMu实例1：1.0.1首次进入空账本首页；导入原版虚构两笔20元后，再记10元，同类别3笔30元；强停重开保存摘要不变。
- 同一实例覆盖安装正式Release后，首页和30元记录保持；连续三次冷启动均保持运行。
- 用户原实例0：此前无重制包，本次仅新装1.0.1并启动，已确认进入空账本首页。没有导入测试流水、读取账本文件或改动原App。
- 11项记账/导入/备份浏览器端到端回归、TypeScript、相关格式检查通过；Release构建、签名和16KB对齐验证通过。
- 本次证据位于 `.tools/mumu-compat`，浏览器结果在 `.tools/e2e-webview-compat`；均不进入Git。MuMu实验依赖和清理说明见LOCAL-TOOLS.md。
