# 第一版交互预览

> 本文是初始预览的历史记录。该版本已隔离到 prototypes/ui-v1；当前正式 App 使用 src/ui、src/core、src/storage、src/imports 和 src/backup，详见根README与TODO。

实现日期：2026-11-08（Asia/Shanghai）。开发根目录：`D:\code\my\2\记账`。

## 本轮目标

用户希望先判断 React + Capacitor 做出的界面是否好看、是否易维护。本轮交付实际 React 应用供点击体验，不将预览描述为已完成的安卓账本产品。

## 布局取舍

- 原版 `activity_main_old.xml` 显示圆形区域、右侧月度收支、主“记一笔”按钮，以及明细/账户/报表/数据四个入口；本次保留这组信息层级。
- `fragment_type_expenses.xml` 使用左右列表、约 1:1.6 的宽度比例；本次保留左一级、右二级的路径。
- `input_view.xml` 包含数字、清空、加减、退格和确认，本次实现相同类别的金额键盘操作。
- `activiry_charge.xml` 包含“保存”和“再记一笔”。本预览的“再记一笔”保留类型、分类、日期和账户，清空金额与备注；这一默认规则尚未通过旧版运行核验。
- 暖白与珊瑚色参考旧资源中的 `main_color`，重新设计间距、组件和夜间主题。原用户自定义背景与实际旧版屏幕未取得，不声称已经完整复原。

## 功能与状态

页面之间有实际状态联动。新建、编辑、删除记录时按 ID 更新，金额使用整数分；报表按二级类别身份汇总，同名但不同父分类不会混在一起。

演示 JSON 备份只接受标识为 `keepaccounts-ui-demo` 的版本 1 数据，并验证 ID、金额、日期、收支类型、分类与账户。恢复为整体替换，不能当作原版 Excel 的兼容导入功能。

本轮使用内存状态，刷新恢复虚构数据。没有服务器、账号、遥测或外部字体/图片请求；前端依赖构建在本机，用户无需提供真实账本。

## 可维护性

UI 在 `pages/`，通用组件在 `components/`，账本规则和测试在 `domain/`；Capacitor 配置只处理原生容器。前端风格通过 CSS 变量统一修改，暖白/夜间共享布局。

依赖由 package-lock.json 锁定，使用 TypeScript 校验、Prettier 格式化和 Vitest 规则测试。正式版需要用独立的数据访问层增加可靠存储和迁移，再补上 Android 原生返回、文件选择/分享、备份及升级测试。

对这类以表单、列表、报表为主的个人记账工具，React + Capacitor 适合快速迭代。复杂原生桌面组件、后台任务、复杂手势和动画需要专门插件/原生实现。

## 本轮验证

- TypeScript 检查与 Vite 生产构建通过。
- 9 项金额、记录身份、分类统计、账户余额、日期和演示备份测试通过。
- 在 390 × 844 的浏览器视口中检查首页、两级分类和数字键盘。
- UI 实测 `12.5 + 0.2` 得到 `12.70`；“再记一笔”清空输入并保留所选分类。
- 保存后本月支出由 `2,060.80` 变为 `2,073.50`；餐饮/早餐由 1 笔 `12.00` 变为 2 笔 `24.70`。
- 上述均使用本项目构造的虚构记录，不涉及用户账本。
