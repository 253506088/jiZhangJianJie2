## 已证实的结构与转换

- `expenses` / `income` / `transfer` / `borrow`保存四种明细。`time_sequence`是这些明细的索引，不再次当作交易导入。转换校验类型、时间标识、原日期、成员和起止账户的多重集一致性，矛盾时整份拒绝。
- 支出金额等以十进制文本保存，日期为墙钟时间文本。新版转为整数分并保留日期时间，不根据`time_span`臆造记账日期。不按相同日期金额备注删除独立记录。
- `expenses_left`是支出一级分类，`expenses_right.key/value`是完整父子名称。`key=常用`时`usually_key`引用真实父分类，属于快捷入口，不创建第二份财务分类。源流水若直接写`type_main=常用`则因真实归属未验证而拒绝，不猜分类。
- `income_type`是单层收入类型，映射至新版隐藏“收入”父类下的叶子。不同父类下相同子类继续独立。
- `account_type.money`是旧版当前余额。按已验证现金方向汇总全部源流水后，使用“源当前余额 − 净变动”推导新版期初余额，再检查各账户最终余额等于源值。该等式是余额迁移计算，不独立证明分类和每笔金额正确；仍需年度Excel对账。
- `member`和`borrow_member`分别对应普通成员和借贷人。四借贷类型的现金方向见LEGACY-FORMAT.md。借贷人源余额与明细净额不一致时会明确提示，源余额保留于附属资料，新版借贷统计不自动虚构期初交易。
- `budget.type/total/expenses`对应预算目标、额度、日/周/月周期。转换为新版独立循环预算；“总体预算”优先解释为全账本目标，不因存在同名分类而改为分类预算。
- 本样本数据库没有账本名称或多个账本的关系表，因此不能宣称单个.db一定包含旧App所有账本。导入要求用户给新账本命名；多账本需分别核对原版备份范围。

## 新版的选择和兼容边界

入口为首页空账本提示或“数据与设置 → 从旧版初始化 → 从旧版 .db 初始化”，与本App `.jzbackup` 覆盖恢复分开。导入创建独立账本，保留现有账本和外观设置；不会往已有Excel导入账本中混写或自动合并。相同SHA-256已导入的文件被阻止，后来删除记录也不恢复为重复记录。

目前接受已验证的4.8.8/结构版本16及精确表列布局。未知版本、未知表、视图/触发器、非空未知自动记账金融表、损坏库、无法关联的方向/索引和无效金额都会拒绝整份导入。不是通用SQLite恢复器，不执行原库SQL脚本、扩展、外部URI或附件路径。

全部原表字段会保存在 `ImportBatch.legacyDb`，只留在本机并随新版完整备份保留，默认预览和报表不输出其原字段值。其必需表/列、数据类型和总量均有模型校验。旧版图标/快捷入口、模板、通知提醒、照片路径、利息设置等没有足够业务格式证据的内容会明确列为“已保留但未启用”，须阅读迁移范围后勾选确认；路径并不等于包含图片文件。主题和首页背景不在这份数据库中，需要重新设置。没有把未启用功能称为完整复刻。

解析通过随App打包的sql.js/WASM在可终止Worker中执行，文件上限64 MiB，解析60秒超时；不依赖网络、REA Node运行时或新增原生权限。实际持久化仍由现有仓库原子提交。转换后连同源资料、合并现有状态的完整快照均不得超过64 MiB，以保证能够保存和完整备份。失败或取消不改现账本。
