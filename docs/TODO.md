# 简洁记账重制 · 执行清单

目标：独立、离线可用的 Android App；延续旧版 UI/操作习惯；用户手动导入原 App 的 Excel 后，分类可继续使用，新旧流水在同一分类下正确统计。每项通过对应检查后勾选，并以同名里程碑单独提交、推送。

## 里程碑

- [x] **M01 — 项目隔离与版本管理**：冻结 UI 预览，建立正式开发入口、Git 远端、忽略规则、需求与决策记录；两个入口构建与 9 项测试通过，忽略规则已核对。
- [ ] **M02 — 旧版操作与 Excel 格式取证**：在无真实数据的环境调查原 App，取得虚构导出样本或可靠的格式证据，记录列、日期、金额、分类/账户/账本映射及未知项。
- [x] **M03 — 正式账本模型与可靠存储**：稳定分类 ID、父子关系、账户/账本、整数金额、原子写入、版本校验与异常恢复；首次创建数据库为空账本。27项核心+7项存储测试通过，原生SQLite插件编译通过；UI接入与安卓实际重启验收在M05/M09完成。
- [ ] **M04 — Excel 导入与初始化**：支持 .xls/.xlsx 解析、字段映射/校验、错误行报告、导入预览、原子应用、分类重建及批次重复检测；不能静默漏账或误删真实重复记录。（解析与初始化模块14项测试通过；正式页面端到端验收进行中）
- [ ] **M05 — 核心 UI 与日常操作**：首页、两级分类、数字键盘、保存/再记一笔、明细搜索/编辑/删除、分类创建/重命名/排序/合并、账户与账本管理；持久化成功后才反馈保存成功。
- [ ] **M06 — 报表与历史分类修复**：按稳定关联统计、完整路径区分同名子分类、可预览的分类合并、月份/账户/账本筛选和统计钻取；覆盖用户所述换机 BUG 的回归场景。
- [ ] **M07 — 完整备份与数据工具**：可手动导出/恢复完整数据，备份校验、覆盖前保护、导入历史、失败恢复与明确的隐私行为；验证备份往返不损失关系。
- [ ] **M08 — 安卓原生整合与可安装包**：独立包名、系统返回、安全区/键盘、文件选择/保存、持久化、离线行为；可重复构建和签名，密钥保持本地。
- [ ] **M09 — 端到端与兼容性验收**：实际导出虚构样本 → 导入 → 继续记账 → 统计合并；重复导入、异常/边界数据、重启持久化、备份恢复、安卓安装运行与截图。
- [ ] **M10 — 交付与维护资料**：可安装 APK、本地签名维护说明、构建/测试/导入指南、兼容范围与已知限制、清理说明；所有里程碑提交与远端同步核对。

## 必须满足的回归场景

- [ ] 历史“支出 / 餐饮 / 早餐”两笔共 20 元，导入后直接选择原两级分类，再记 10 元，报表为 3 笔 30 元。（核心回归已通过，待真实Excel文件路径与UI端到端验收）
- [ ] “餐饮 / 其他”和“交通 / 其他”分开；同名收入/支出分类分开；不同账本的分类范围明确。
- [ ] 分类改名不割裂历史统计；合并分类不删除流水，并同步模板/其他引用（如实现）。
- [ ] 真实存在的相同日期、金额、备注的两笔流水都保留；重复导入同一批文件有明确处理。
- [ ] 导入/备份恢复失败时旧数据保持完整；金额、日期、备注、账户和账本不静默丢失。
- [ ] App 重启后数据仍在；演示预览不会污染正式账本。
