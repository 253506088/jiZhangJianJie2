# 简洁记账重制 · 执行清单

目标：独立、离线可用的 Android App；延续旧版 UI/操作习惯；用户手动导入原 App 的 Excel 后，分类可继续使用，新旧流水在同一分类下正确统计。每项通过对应检查后勾选，并以同名里程碑单独提交、推送。

## 里程碑

- [x] **M01 — 项目隔离与版本管理**：冻结 UI 预览，建立正式开发入口、Git 远端、忽略规则、需求与决策记录；两个入口构建与 9 项测试通过，忽略规则已核对。
- [x] **M02 — 旧版操作与 Excel 格式取证**：未修改APK已在空白ARM环境运行并正常导出13KB虚构样本，四张工作表与实际表头/日期金额已记录，3项原样夹具验证通过。借贷/成员的进一步行为语义仍继续调查并纳入M05/M06/M09，不把空工作表当作这些行为已验证。
- [x] **M03 — 正式账本模型与可靠存储**：稳定分类 ID、父子关系、账户/账本、整数金额、原子写入、版本校验与异常恢复；首次创建数据库为空账本。27项核心+7项存储测试通过，原生SQLite插件编译通过；UI接入与安卓实际重启验收在M05/M09完成。
- [x] **M04 — Excel 导入与初始化**：.xls/.xlsx 解析、字段映射/校验、错误行报告、导入预览、原子应用、分类重建及批次重复检测完成。原包虚构四类型样本回归通过；API36系统文件选择器实际导入两笔20元，继续记账后同类别3笔30元，强制停止重启保持。全模块测试140项通过；最终整体验收见M09。
- [x] **M05 — 核心 UI 与日常操作**：概况/经典首页、四种记账类型、两级支出/单层收入、成员/借贷人、数字键盘、原版再记行为、明细搜索编辑删除、分类排序归档合并、账户账本和模板管理完成。29项浏览器端到端全过，Android返回/系统键盘/取消未保存内容/夜间模式通过；正式与演示数据库独立。
- [x] **M06 — 报表与历史分类修复**：稳定关联与完整父子路径、收入/支出/账本隔离、分类重命名/合并及别名、报表筛选钻取均通过。导入后直接续记3笔30元已在真实系统文件路径验收；独立周期预算和结余率的源行为回归通过。
- [x] **M07 — 完整备份与数据工具**：明文/加密完整备份、显式覆盖确认、历史保存点、导入历史和Excel导出完成。浏览器备份3项与Excel4项端到端通过；API36实际SAF保存文本/Excel、取消、错误密码不写库和正确密码逐字段恢复通过。10000笔约4.8MB备份写后核对无损。
- [ ] **M08 — 安卓原生整合与可安装包**：独立包名、系统返回、安全区/键盘、文件选择/保存、持久化、离线行为；可重复构建和签名，密钥保持本地。
- [ ] **M09 — 端到端与兼容性验收**：实际导出虚构样本 → 导入 → 继续记账 → 统计合并；重复导入、异常/边界数据、重启持久化、备份恢复、安卓安装运行与截图。
- [ ] **M10 — 交付与维护资料**：可安装 APK、本地签名维护说明、构建/测试/导入指南、兼容范围与已知限制、清理说明；所有里程碑提交与远端同步核对。

## 必须满足的回归场景

- [x] 历史“支出 / 餐饮 / 早餐”两笔共20元，导入后直接选原两级分类记10元，报表3笔30元。核心/浏览器及API36原生均通过；原生夹具使用原包内新建的FixtureFood/FixtureBreakfast虚构分类。
- [x] “餐饮 / 其他”和“交通 / 其他”分开；同名收入/支出分类分开；不同账本的分类范围明确。
- [x] 分类改名不割裂历史统计；合并分类不删除流水，并同步模板/预算及路径别名。
- [x] 相同日期、金额、备注的两笔独立流水都保留；重复导入同一批文件有明确处理。
- [x] 导入/备份恢复失败时旧数据保持完整；金额、日期、备注、账户和账本不静默丢失。
- [x] App 重启后数据仍在；演示预览不会污染正式账本。
