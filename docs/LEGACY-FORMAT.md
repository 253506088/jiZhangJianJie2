## 已确认的Excel结构

- 容器是 OLE/BIFF `.xls`（不是把网页改扩展名，也不是xlsx）。
- 固定四张表：**支出、收入、转账、借贷**，空表仍保留三行元信息/表头。
- 第1行是类型名，支出/收入可能带合计；第2行是“时间”和导出范围；第3行是表头；第4行起才是流水。
- 两笔实测支出的金额为文本 `10.00`，日期为文本 `yyyy-MM-dd HH:mm`，不是Excel序列值。
- 账本由导出前当前所选账本决定；本样本列中没有账本名。

| 工作表 | 表头（按原顺序） |
| --- | --- |
| 支出 | 金额、支出大类、支出小类、账户、时间、成员、备注 |
| 收入 | 金额、收入类别、账户、时间、成员、备注 |
| 转账 | 金额、转账类型、原账户、目标账户、时间、成员、备注 |
| 借贷 | 金额、借贷类型、账户、借贷人、时间、备注 |

原版收入是单层类别，不能假定与支出一样有两个原始分类字段。借贷类型的具体值、它对收支/余额的影响与非默认成员正在进一步用虚构数据验证；当前样本中对应表为空。

后续完整8笔原样样本已覆盖这些字段：成员FixtureMember，借贷人FixtureLender；借贷类型为借入/借出/还款/收款，普通转账的“转账类型”列实际为空。借贷本金不计普通收入支出，现金方向分别增加/减少/减少/增加，详见fixtures说明。

## 已确认的界面行为

- 首次启动选择主题，默认蓝色，并可选粉、黄、红、棕、绿、灰、蓝绿。
- 实际默认首页是预算与收支概况，含日/周/月预算卡片、记账入口与底部导航，并不等同于仅从old目录布局推测出的首页。
- 记账页有支出/收入/转账/借贷四个页签，以及账户、成员/借贷人、日期时间、备注等字段。
- 从首页进入记账页时数字键盘自动展开。保存“再记一笔”后金额清零、键盘重新出现，所选分类继续可用，时间更新为当前时刻。
- 是否在手动选定历史日期后也重置到今天、日/周预算的计算方式、借贷的完整操作语义，仍以进一步实验为准。

## 后续控制实验的确定结果

- 收入、转账和借贷的“再记一笔”都会返回支出；清金额与备注，更新时间。历史日期11/1也会恢复到设备当前11/7。
- 普通收入/转账保留原账户和成员；借贷结束后恢复的是此前普通记账的账户/成员，不把借贷联系人带过去。
- 日、周、月预算独立。普通支出20时分别设置日100、周700、月3000，首页余额为80/680/2980；没有对应预算时显示0。
- 周一为本周边界：11/7周六时加入11/1周日支出，不影响当日/本周余额，但影响当月。
- 无总体预算时只扣已配置预算类别覆盖的支出：仅交通日预算50、当日其他类别支出21，首页剩余为50；交通条目也是0/50。
- 月余额圆环属于普通收入结余比例而非预算比例。收入200、支出20显示90%；支出21时89.5%显示89%，按整数截断；预算金额改变不影响这一比例。
- 原版预算余额视觉只显示一位小数（2975.79显示2975.8），新版保留两位分值是明确的精度改进。
- 负金额正常保存被拒，Toast“金额不能为负哦”；显式0金额也被拒，Toast“请输入金额~~”。没有成功写入负/零流水。新版不能把未知负值默默转成正消费。
